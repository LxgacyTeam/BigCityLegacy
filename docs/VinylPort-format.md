# VinylPort: формат паков и совместимость

Новый экспорт использует `<VinylPack version="4" car="Gaz21">`. Это версия формата файла, а не версия игры или плагина. Импорт принимает версии 1–4; отсутствие версии, неверный номер или более новая версия отклоняются до загрузки машины. Старые паки версий 1–3 читаются с теми же проверками содержимого.

Пак содержит `CarPaint/Items`, необязательный штатный `CarMaterial` и необязательный `EnhancedBodyPaint`. Двигатель, привод и подвеска не экспортируются. При импорте остальные узлы сохранения машины остаются на месте.

Штатные поля `size_y` и `acpect` могут быть отрицательными: знак влияет на отражение винила. Импорт, экспорт и замена текста примитивом сохраняют эти значения во всех поддерживаемых версиях. Нулевые размеры и нечисловые значения отклоняются.

## Текстовые винилы

```xml
<Item pos="-0.9 0.1 0" rot="0 90 0" size_y="0.246" acpect="4.16"
      depth="2.5" color="1 1 1 1" sprite.name="ECT.Text"
      ect.text="MAD OUT 2" ect.font="1" ect.style="3" ect.symmetry="1" />
```

- `ect.text`: до 80 символов UTF-16, без управляющих символов; пустая строка допускается для редактирования.
- `ect.font`: 0–2, один символ. Порядок шрифтов соответствует EnhancedCarTuning.
- `ect.style`: 0 — обычный, 1 — жирный, 2 — курсив, 3 — жирный курсив.
- `ect.symmetry`: необязательное значение 0 или 1; разрешено также для обычных винилов.
- Старое внутреннее имя `ect.text.v1:<font>:<style>:<UTF8Base64>` читается и преобразуется в поля выше. Неполные, противоречащие друг другу или повреждённые поля отклоняются.

Если текстовые слои есть, а рабочий EnhancedCarTuning не загружен, VinylPort открывает модальное окно LegacyUIFramework. Можно отменить импорт или заменить текстовые слои штатными примитивами. Используется `Primitive_1` из каталога игры, при его отсутствии — доступный примитив из той же категории. Положение, поворот, размер, глубина, порядок слоёв и цвет сохраняются. Если примитив недоступен, импорт отклоняется. Исходный `.vinyl` не изменяется.

## Цвет кузова и отдельных деталей

Общий цвет остаётся в штатном `CarMaterial/Body`. Цвета деталей переносятся отдельно:

```xml
<EnhancedBodyPaint version="1">
  <Part id="Hood" color="1 0 0" metallic="0.7" gloss="0.8" />
  <Part id="Doors" color="0 0 1" metallic="0.2" gloss="0.4" />
</EnhancedBodyPaint>
```

Допустимые детали: `Body`, `Hood`, `Front`, `Trunk`, `Rear`, `Doors`. Каналы RGB, metallic и gloss находятся в диапазоне 0–1. Одна деталь может встретиться только один раз. Секция требует наличия штатного `CarMaterial` в паке.

Пак с `CarMaterial` заменяет общий цвет и набор индивидуальных цветов. Если индивидуальных цветов в таком паке нет, прежние переопределения удаляются. Пак без `CarMaterial` меняет только винилы и сохраняет существующую покраску.

Без совместимого EnhancedCarTuning окно предупреждает, что виден только общий цвет. Индивидуальные цвета остаются в импортируемом XML, но штатное последующее сохранение без плагина может удалить неизвестную секцию. Для полноценного переноса цветов и экспорта текущих изменений нужны обе обновлённые сборки: BigCityLegacy и EnhancedCarTuning с `VinylPortBridge`.

Экспорт берёт текущее состояние гаража, включая изменения деталей в открытом колорпикере, без временной подмены PlayerPrefs. После импорта панель покраски обновляет текущий цвет и исходное состояние для последующих изменений и отмены.

## Проверки перед выпуском

Автоматические проверки формата: `dotnet run --project tests/VinylPackTests/VinylPackTests.csproj -c Release`. Проверки сессии покраски находятся в проекте `EnhancedCarTuning.BodyPaintTests`.

В игре проверить: экспорт текста с кириллицей и стилями; импорт с обоими плагинами и после перезапуска; импорт без EnhancedCarTuning с отменой и заменой текста; загрузку общего цвета без цветов деталей; сохранение двигателя и подвески; закрытие предупреждения крестиком; работу выбора деталей и колорпикера после импорта.
