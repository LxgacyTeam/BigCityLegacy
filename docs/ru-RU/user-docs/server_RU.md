# Сервер

Настройки игрового сервера задаются в `BigCityLegacy/config/ServerConfig.toml`. Шаблон находится в `config_example/ServerConfig.toml`; при отсутствии стандартного файла сервер создаёт его автоматически.

```text
game.exe -bend_GameServer -batchmode -nographics
game.exe -bend_GameServer -batchmode -nographics -serverConfig:"C:\Servers\race.toml"
```

Флаг `-bend_GameServer` обязателен для запуска сервера и не является параметром TOML. `-serverConfig` выбирает файл, но не включает серверный режим. Обычный игровой клиент не читает серверный конфиг. Явные аргументы запуска имеют приоритет над значениями TOML и их алиасами. Пустые пути используют стандартные файлы; относительные пути вычисляются от корневой папки игры. Для Windows-путей удобно использовать одинарные кавычки.

`masterServer = true` включает mirror вместе с игровым сервером и является значением по умолчанию. Для отдельного игрового сервера без mirror укажите `masterServer = false`. Порт mirror задаётся через `masterPort` в TOML либо `-masterPort:<порт>`. В `ServersList.json` хранятся список серверов и интервалы опроса.

| Секция | Параметры |
| --- | --- |
| `server` | `port` (1–65535), `maxConn` (1–100), `Mode` (`None`, `RP`, `Race`, `CS`, `CS_Sur`), `lang`, `maxCars`, `maxCarsByPlayer`, `maxVinylLayers`, `CarSpawnTimeout`, `maxNikLength`, `idleKickTimeout`, `disconnectedKickTimeout`, `noChatEvents`, `noKillChat`, `noCsDamageCooldown`, `useVanillaRespawn`, `requireFingerprint` |
| `plugins` | `noPluginsPolicyAndAlerts` |
| `mirror` | `masterServer` (по умолчанию `true`), `masterPort` (по умолчанию `35000`), `masterDebug` |
| `files` | `serversList`, `eventsDir`, `respawnPoints`, `banList`, `pluginsPolicy`, `alerts` |
| `console` | `noServerConsole`, `noServerCli`, `verboseServerConsole`, `noUpdCheck` |
| `logging` | `logsDir`, `noLogging`, `chatLogging`, `logLevel` |


Пример конфигурации:

```toml
# BigCityLegacy server configuration. CLI arguments override these values.
# Keys match launch options without the leading '-'.

[server]
port = 7800
maxConn = 16
Mode = "None"
lang = "en"
maxCars = 100
maxCarsByPlayer = 15
maxVinylLayers = 1024
CarSpawnTimeout = 1000
maxNikLength = 20
idleKickTimeout = "120s"
disconnectedKickTimeout = "30s"
noChatEvents = false
noKillChat = false
noCsDamageCooldown = false
useVanillaRespawn = false
requireFingerprint = false

[plugins]
noPluginsPolicyAndAlerts = false

[mirror]
masterServer = true
masterPort = 35000
masterDebug = false

[files]
# Relative paths resolve from the game directory. Empty values use defaults.
serversList = ''
eventsDir = ''
respawnPoints = ''
banList = ''
pluginsPolicy = ''
alerts = ''

[console]
noServerConsole = false
noServerCli = false
verboseServerConsole = false
noUpdCheck = false

[logging]
logsDir = ''
noLogging = false
chatLogging = false
logLevel = "Log"
```


Сервер игры глобально умеет работать в 2 режимах: **Master** и **Base**

**Base** — игровой сервер без mirror (`masterServer = false`).
**Master** - это Mirror + Game Server, то есть помимо игрового сервера, запускается еще и mirror. Master сервер в таком случае должен стать главным в архитектуре из нескольких игровых серверов, связывающий их всех.

# Game Server

**Game Server** - игровой сервер, представляющий собой сам сервер игры, то есть одно онлайн-лобби.

Game Server имеет 5 режимов: `None`, `RP`, `Race`, `CS`, `CS_Sur`

* **None** - базовый режим, обозначаемый в игре как FreeRoam. На нем же базируются все остальные режимы.

- **RP** - режим None, но с отключенным оружием.
- **Race** - режим None, но с периодически запускаемыми ивентами в виде онлайн-гонок
- **CS** - режим None, но с периодически запускаемыми ивентами "Копы против Бандитов" (фактически team deathmatch)
- **CS_Sur** - режим None, но с периодически запускаемыми ивентами "Survival" (фактически deathmatch, FFA)

Game Server настраивается через TOML и параметры запуска (см. Параметры запуска) и поддерживает администрирование через интерактивный CLI интерфейс (см. ниже)

Фактического ограничения на кол-во игроков на сервере нет, но игра расчитана на **не более чем 100 игроков**

# Mirror сервер

**Mirror сервер** - сервер, обрабатывающий список игровых серверов и их состояние. Он отдает клиенту игры список доступных серверов, их настройки и текущий онлайн. То есть именно он определяет что игра покажет в списке серверов в разделе "**Онлайн**". Mirror умеет принимать и отдавать клиенту название сервера, макс кол-во игроков, язык, режим игры, расположение в группе и некоторые другие параметры. Также именно mirror обеспечивает функцию автоматического выбора сервера (при нажатии на зеленую кнопку Connect в игре).

Настройка Mirror сервера осуществляется в отдельном JSON конфиге. По умолчанию он хранится в `BigCityLegacy/config/ServersList.json`. Пример конфига выглядит так:

```json
  {
  "version": 1,
  "pollIntervalMs": 1500,
  "staleAfterMs": 6000,
  "servers": [
    {
      "id": "master-self",
      "name": "RU FreeRoam #1",
      "connectIp": "127.0.0.1",
      "queryIp": "127.0.0.1",
      "port": 7800,
      "maxPlayers": 16,
      "lang": "ru",
      "menuGroup": "FreeRoam",
      "serverMode": "None",
      "onlineProtocolVersion": 94,
      "includeInAuto": true,
      "showIfOffline": false,
      "self": true
    }
  ]
}
```

**Рассмотрим назначение параметров:**

`pollIntervalMs` - интервал опроса игровых серверов (онлайн ли)

`staleAfterMs` - определяет через сколько времени запись считается устаревшей, если сервер более недоступен

`servers` - массив игровых серверов, отображаемых в списке

`id` - уникальный id для каждого сервера

`name` - имя сервера, отображаемое в меню

`connectIp` - публичный IP сервера, передаваемый клиенту игры

`queryIp` - IP сервера для опроса mirror'ом (если сервер находится в той же локальной сети/на том же компьютере, удобно разделять публичный и внутренний IP)

`port` - порт сервера, передаваемый клиенту игры

`maxPlayers` - макс. кол-во игроков на сервере, отображаемое в меню

`lang` - язык сервера, отображаемый в меню

`menuGroup` - в какой категории в меню игры отображать сервер. Принимает значения `FreeRoam`, `RP`, `Race` или `CS`

`serverMode` - режим игры на сервере

`onlineProtocolVersion` — версия онлайна, по умолчанию `94`. Глобальное значение задаётся константой `OnlineProtocolVersion` в `BigCityLegacyPlugin.cs`. Для собственной записи mirror (`self`) используется глобальная версия. Для отдельных записей других серверов можно указать их версию явно. Клиентский аргумент `-onlineVersion:93` понижает версию; значение выше глобального ограничивается глобальным.

`includeInAuto` - будет ли сервер учитываться при авто-подключении

`showIfOffline` - отображать ли сервер в игре, если он офлайн

`self` - обозначает игровой сервер мастера. УКАЗЫВАТЬ ТОЛЬКО 1 РАЗ.

Master сервер необходим, если вы хотите запустить сразу несколько игровых серверов и отображать их списком в игре. Подразумевается и рекомендуется архитектура `1 Master Server + n Base servers`

# Администрирование и CLI интерфейс

В интерактивной Linux-консоли (в том числе tmux) стрелки ↑/↓ перебирают до 100 последних непустых команд. Повторы подряд не добавляются. После последней записи ↓ возвращает незавершённую строку ввода. Доступны ←/→, Home/End, Backspace/Delete и Ctrl+U для очистки строки. Длинный ввод прокручивается по горизонтали; предел строки — 4096 символов. История хранится только до завершения процесса. Вывод логов сохраняет набранный текст. При перенаправленном вводе и в терминале `TERM=dumb` используется обычное чтение строк без интерактивной истории.

Во время работы игрового сервера им можно управлять с помощью интерактивного CLI интерфейса в окне консоли сервера. Поддерживаются слеюущие команды:


| Команда        | Действие                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------------- |
| players               | Вывести текущий список игроков на сервере                    |
| playerinfo {PlayerID} | Отобразить информацию об игроке                                       |
| banlist  | Отобразить текущий список банов                          |
| kick {PlayerID} [reason]       | Кикнуть игрока                                                                       |
| kill {PlayerID} | Убить персонажа игрока. |
| ban {PlayerID} {1/2/3/4} [time] [reason]  | Забанить игрока; 1 = бан по GUID, 2 = бан по IP                           |
| unban {BanID}         | Разбанить игрока по BanID                                                        |
| setprop {PlayerID} {prop} {0/1} [time] | Назначить или снять свойство; `help setprop` |
| tp {PlayerID} {preset/x y z/json} [wcar] | Телепорт по координатам; `help tp` |
| tpto {PlayerID} {to PlayerID} [wcar] | Телепорт к игроку |
| clearchat | Очистить чат |
| help [setprop/tp/alert] | Справка по командам |
| reloadmirror             | Перезагрузить mirror; перечитывает текущий ServersList.json                 |
| reloadcfg             | Перезагрузить конфиги (EventsList, RespawnPoints, BanList, PluginsPolicy, Alerts)                   |
| alert {PlayerID/all} {message} {small/large/hint} [seconds] | Сообщение игроку или всем; `help alert` |
| msg {text}            | Отправить сообщение от имени сервера (см. примечание) |
| cleardrop             | Отчистить весь дроп на сервере (аптечки и оружие)         |
| delcars all           | Удалить все автомобили на сервере                                    |
| delcars {PlayerID}    | Удалить все автомобили отдельного игрока                      |
| stats                 | Вывести статистику потребления и загрузки ресурсов  |
| showcfg               | Вывести текущий конфиг сервера  |
| stop                  | Завершить работу сервера                                                    |

`reloadmirror` работает только при активном mirror: перечитывает ServersList.json без перезапуска игрового сервера, при ошибке оставляет прежний список. `banlist` показывает активные баны, исключая истёкшие и записи Type 0. `showcfg` выводит загруженные при запуске значения ServerConfig с учётом стандартных значений и аргументов запуска.

> [!WARNING]
> На данный момент команда `msg` требует хотя-бы одного игрока на сервере и отправляет сообщение фактически от его имени, лишь подменяя никнейм на "Server". Это обусловлено особенностями текущей архитектуры чата в игре.

#### PlayerID

Каждому игроку на сервере присваивается временный уникальный **PlayerID**, который действует в рамках его текущей игровой сессии. Счетчик PlayerID действует по каждому новому подключению игрока к серверу, никогда не очищается и не уменьшается. Если игрок перезайдет на сервер, получит новый PlayerID, а старый больше никогда не будет использован. PlayerID игроков отображается в списке игроков по команде `players`

#### Баны и свойства игроков

`ban <PlayerID> <1|2|3|4> [time] [reason]` запрещает подключение по GUID (`1`) или IP (`2`). Необязательный срок — положительное целое число с суффиксом `s`, `m`, `h` или `d`: `30s`, `15m`, `12h`, `5d`. Без срока бан постоянный. Пример: `ban 15 1 12h`. Команда `ban` не принимает тип `0`.

GUID принадлежит игровому профилю и хранится в PlayerPrefs. Удаление сохранения создаёт другой GUID; бан по GUID не является защитой от создания нового профиля.

`setprop <PlayerID> <noweapon|nomove|nocars|nochat|invisible> <0|1> [time]` назначает (`1`) или снимает (`0`) свойство. Срок задаётся так же, как для бана; при снятии не используется. Повторное назначение заменяет срок этого свойства. Примеры: `setprop 15 nochat 1 15m`, `setprop 15 nochat 0`.

| Свойство | Действие |
| --- | --- |
| `noweapon` | Запрет стрельбы и установки/активации бомб; выбранное оружие заменяется на руки. |
| `nomove` | Заморозка персонажа с высадкой из автомобиля. Сервер отклоняет перемещение и вход в транспорт; клиент BCL также блокирует управление перемещением. У штатного клиента коррекция позиции использует обычную телепортацию с загрузкой местности. |
| `nocars` | Запрет спавна автомобилей. Уже созданные автомобили сохраняются. |
| `nochat` | Сообщения игрока не отправляются в чат. |
| `invisible` | Скрытие ника, полосы здоровья, метки на карте и строки игрока в списке игроков у клиентов BCL. Сервер не отправляет события чата об этом игроке: подключение, переподключение, выход, смену ника и киллчат. Если невидимый игрок убил другого, сообщение о смерти не раскрывает его ник. Сам персонаж остаётся видимым. Штатный клиент не поддерживает сетевой флаг для скрытия UI и отображает эти элементы по своим правилам. |

При посадке в автомобиль сервер проверяет собственное состояние блокировки. Попытка сесть в закрытую машину приводит к удалению автомобиля и исключению игрока с причиной `Suspicion of cheat usage`. Если запрос указывает на далёкую машину или неверное место, игрок исключается, но машина не удаляется.

Баны и свойства хранятся в `BigCityLegacy/config/BanList.json` (путь задаётся параметром `banList`). Свойства проверяются только по GUID, даже если запись содержит бан по IP. `until` — Unix timestamp в секундах UTC; принимаются JSON-число и строка с числом. Отсутствие `until` означает постоянный срок. У бана и каждого свойства независимые сроки. Истёкшие ограничения не применяются; сервер периодически удаляет их из файла. После ручной правки используйте `reloadcfg`.

```json
{
  "Version": 1,
  "Bans": [
    {
      "BanID": 1,
      "GUID": "1d9b4ba4-76f9-417f-b275-49e863726cb7",
      "IP": "1.2.3.4",
      "Type": 0,
      "Nickname": "BadPlayer",
      "Props": [
        { "Prop": "noweapon", "until": 1792388642 },
        { "Prop": "nochat" }
      ]
    }
  ]
}
```

`Type`: `0` — только свойства, без бана; `1` — бан по GUID; `2` — бан по IP. Временный бан содержит собственное поле `until` рядом с `Type` и `Nickname`.

`unban <BanID>` снимает бан. Если есть свойства, запись сохраняется с `Type: 0`; иначе удаляется. Сами свойства команда `unban` не снимает. `playerinfo <PlayerID>` показывает активные свойства отдельной строкой, например `Props: noweapon (5h), nochat (perm)`.

При кике и бане чат сообщает причину выхода и срок бана вместо обычного `- disconnected`. Назначение ограничений оружия, машин, чата и движения также объявляется в чате, если включены сообщения о событиях.

#### Телепортация и очистка чата

`tp <PlayerID> <точка|x y z|json> [wcar]` принимает имя готовой точки, координаты с десятичной точкой или JSON из Point Tool, например `tp 15 police`, `tp 15 100.5 20 -30` либо `tp 15 {"x":100.5,"y":20,"z":-30,"yaw":90} wcar`. JSON обязан содержать `x`, `y`, `z`; `yaw` необязателен. Готовые точки содержат координаты и направление взгляда: police, park, airport, sto1, sto2, sto3, sto4, desert, mountain, cemetry, derbyarena, mansion, farm. Имена не зависят от регистра. Без `yaw` поворот сохраняется. `tpto <PlayerID> <to PlayerID> [wcar]` переносит к текущей позиции другого игрока. С `wcar` перемещается автомобиль вместе со всеми пассажирами, если персонаж находится в машине; без него персонаж высаживается. Телепортация сохраняет здоровье и использует штатную загрузку местности; замороженный персонаж остаётся замороженным в новой точке. Пример: `tpto 15 16 wcar`.

`kill <PlayerID>` обнуляет здоровье персонажа через штатную серверную систему смерти. `kick` и `ban` немедленно удаляют игровую сессию и персонажа; `disconnectedKickTimeout` применяется только к оборванным соединениям, а не к административному удалению.

`clearchat` очищает серверную историю и вытесняет текст из истории штатных клиентов пустыми сообщениями через существующий RPC. Новый клиентский протокол не требуется. Подсветка пустых строк исчезает с обычным временем подсветки чата.

`help` выводит краткий список команд; `help setprop` и `help tp` — подробную справку с примерами.

Во время активного матча CS/CS_Sur фрирум-персонаж погибает после пяти секунд в зоне матча. Автомобиль, на котором он въехал в зону, также удаляется после пяти секунд, даже если игрок успел выйти. Машина, покинувшая зону, и транспорт с участниками ивентов не удаляются; пассажиры перед удалением высаживаются.

## Логирование и диагностика

При каждом запуске сервера создаётся отдельный файл `serverlog_<port>_<yyyy-MM-dd_HH-mm-ss-fff>.log`. Время в именах и записях — UTC. Файл содержит сообщения Unity из всех потоков, логи BepInEx без повторного копирования Unity и логический вывод консоли BCL, включая введённые CLI-команды. Записи содержат уровень, источник и номер потока; переданный Unity stack trace сохраняется. Записи сбрасываются в файловую систему сразу, история в памяти BCL не накапливается. Файлы создаются атомарно и не перезаписываются при совпадении времени запуска нескольких экземпляров. Старые файлы сохраняются без автоматического удаления.

`chatLogging = true` в `[logging]` или аргумент `-chatLogging` включает отдельный файл `chatlog_<port>_<yyyy-MM-dd_HH-mm-ss-fff>.log`. Эта настройка независима от `noLogging` и уровня серверного лога.

По умолчанию логи хранятся в `BigCityLegacy/logs`

Параметры секции `[logging]` доступны также как аргументы запуска:

| TOML | Аргумент | Назначение |
| --- | --- | --- |
| `logsDir = ''` | `-logsDir:"server-logs/instance-1"` | Папка логов. Пустое значение использует `BigCityLegacy/logs`. Относительный путь отсчитывается от папки игры; поддерживаются абсолютные пути. Папка создаётся автоматически. |
| `noLogging = false` | `-noLogging` | Отключить файловый лог BCL; по умолчанию он включён. |
| `chatLogging = true` | `-chatLogging` | Включить лог чата; по умолчанию выключён. |
| `logLevel = "Log"` | `-logLevel:Warning` | Минимальный уровень: `Log`, `Warning`, `Error`, `Exception`, от менее к более серьёзному. `Assert` записывается как `Error`. |

Подробная диагностика доступна в Debug-сборке с аргументом `-serverDiagnostics`; для полной трассировки задайте `logLevel = "Log"`. Диагностика пишет `ENTER`/`EXIT`/`THROW` с ID операции, родительским ID и глубиной вложенности вокруг получения сетевых буферов, диспетчеризации UNet, подключения игроков, спавна автомобилей, загрузки XML и назначения родительских объектов. Указываются размеры строк/буферов, позиции чтения, тип сообщения, канал, ID соединения и сетевого объекта, когда доступны. Трассировка не читает и не изменяет пакет, не сохраняет его содержимое и содержимое XML. При глубине 32 и 64 сохраняется текущий managed stack trace; каждые 30 секунд — сведения о памяти, GC и числе игроков. Диагностика повышает нагрузку на диск и включается для расследования. При `noLogging = true` она отключена; в обычном режиме её сетевые патчи не устанавливаются.

Штатный `m_log_<port>.log` по умолчанию отключён. Аргумент **`-mlog`**, переданный при запуске, включает его независимо от лога BCL

## Проверка плагинов и версии BCL

При подключении клиент BCL передаёт версию самого BigCityLegacy и список загруженных BepInEx-плагинов: GUID, версию и название. DLL-зависимости и файлы, которые BepInEx не загрузил как плагины, в список не входят. Решение о допуске принимается до создания игрового персонажа. `playerinfo <PlayerID>` показывает полученный список плагинов.

Правила задаются в `BigCityLegacy/config/PluginsPolicy.json`. Отдельные настройки `allowClientsWithoutManifest` и `allowClientsWithoutBclVersion` определяют допуск при отсутствии списка плагинов и версии BCL соответственно. По умолчанию обе равны `true`, `bcl` равен `null`, оба списка пусты. Это сохраняет допуск ванильных и старых клиентов. Чтобы требовать обе части отчёта, установите обе настройки в `false`.

`[plugins] noPluginsPolicyAndAlerts = true` или аргумент `-noPluginsPolicyAndAlerts` полностью отключает серверную проверку плагинов/версии BCL и отправку Alerts. Оба файла не читаются; обычные баны продолжают работать. Настройка применяется при запуске.

```json
{
  "version": 1,
  "allowClientsWithoutManifest": false,
  "allowClientsWithoutBclVersion": false,
  "bcl": {
    "minVersion": "1.4.2",
    "message": "BigCityLegacy {pluginVersion} is not supported. Required: {requiredVersion}.",
    "messageRu": "BigCityLegacy версии {pluginVersion} не поддерживается. Необходима версия: {requiredVersion}."
  },
  "hardlist": [
    {
      "guid": "com.bigcitylegacy.enhancedcartuning",
      "name": "EnhancedCarTuning",
      "minVersion": "1.0.0",
      "extra": "Install the required plugin before reconnecting.",
      "extraRu": "Перед повторным подключением установите необходимый плагин."

    }
  ],
  "blacklist": [
    {
      "guid": "com.example.prohibited",
      "message": "Remove {pluginName} before joining.",
      "messageRu": "Удалите {pluginName} перед подключением."
    }
  ]
}
```

`hardlist` требует наличие указанного GUID и соответствие его версии. `blacklist` запрещает GUID; если указана версия или диапазон, запрещены только совпадающие версии. GUID сравниваются без учёта регистра; название служит для отображения. `version` означает точное совпадение, `minVersion` и `maxVersion` — включительные границы. Вместо `version` можно использовать один или оба предела. `1.4` равняется `1.4.0.0`; prerelease ниже соответствующего релиза, build metadata не влияет на сравнение. Секция `bcl` задаёт независимое правило версии самого BCL. Если версия передана и не соответствует правилу, клиент отклоняется даже при разрешении отсутствующей версии.

`message` в правиле заменяет общий шаблон несовместимости для этого плагина; `extra` добавляет абзац к сообщению. Это применимо также к секции `bcl`. Все найденные несовместимости выводятся вместе. Если нет имени отсутствующего плагина, используется `name` из правила или его GUID.

Если отсутствие отчёта разрешено, список hardlist/blacklist для такого клиента проверить невозможно; отсутствующая версия BCL также не проверяется при соответствующем разрешении. Повреждённый переданный отчёт не считается отсутствующим и отклоняется. Это модель совместимости по данным клиента, а не средство доказательства отсутствия читов: изменённый клиент может подделать отчёт.

Размеры отчёта ограничены: до 256 плагинов, GUID/название до 128 символов, версия до 64, двоичный отчёт до 20000 байт и XML подключения вместе с отчётом до 30000 байт. Если полный список не помещается, клиент отменяет подключение и показывает причину; частичный список не отправляется. Канал использует дополнительные атрибуты XML штатного подключения, которые старый сервер игнорирует. Online protocol version остаётся 94.

## Сообщения игрокам

Шаблоны находятся в `BigCityLegacy/config/Alerts.toml`. Секции: `plugins`, `missingManifest`, `missingBclVersion`, `invalidManifest`, `banRejected`, `banned`, `kicked`, `welcome`. Каждая поддерживает `enabled`, `title`, `message`, `display`, `duration`. Пропущенные секции используют стандартные шаблоны. По умолчанию `welcome` отключён, остальные включены; тип — `small`, кроме стандартного `welcome` (`large`).

`small` — перетаскиваемое окно с HintBox; `large` — окно со ScrollView; `hint` — HintBoxAlt сверху экрана на `duration` секунд (0.1–3600, по умолчанию 6). Длинное small-сообщение автоматически получает прокрутку. Hint не блокирует ввод; открытый диалог показывает курсор и блокирует клики в игру. Сообщения об отказе/кике переживают отключение от сервера. Очередь ограничена; длительность hint отсчитывается с показа, а не с получения.

`titleRu` и `messageRu` в каждой секции Alerts.toml необязательны. Русский язык выбирается по текущему языку игры на клиенте. При отсутствии или пустом русском поле используется основной текст. В PluginsPolicy.json доступны `messageRu` и `extraRu` для каждого правила, включая `bcl`.

```toml
[welcome]
enabled = true
title = "Server rules"
titleRu = "Правила сервера"
display = "large"
message = """
Welcome, {nickname}!
1. Respect other players.
2. Follow the server rules.
"""
messageRu = """
Добро пожаловать, {nickname}!
1. Уважай других игроков.
2. Соблюдай правила сервера.
"""
updatedAt = 1793150000

[kicked]
title = "Disconnected by administrator"
titleRu = "Отключен администратором"
message = "{nickname}, you were kicked.\nReason: {reason}"
messageRu = "{nickname}, вы были отключены от сервера.\nПричина: {reason}"
display = "small"

[plugins]
title = "Plugin compatibility"
titleRu = "Совместимость плагинов"
message = "{reason}\n{pluginName}: {pluginVersion}\nRequired: {requiredVersion}"
messageRu = "{reason}\n{pluginName}: {pluginVersion}\nНеобходима: {requiredVersion}"
display = "small"

[banned]
title = "Banned!"
titleRu = "Вы были забанены!"
message = "{nickname}\nBan ID: {banId}\nDuration: {duration}\nReason: {reason}"
messageRu = "{nickname}\nID бана: {banId}\nДлительность: {duration}\nПричина: {reason}"
display = "hint"
duration = 15
```

В двойных строках используйте `\n` для переноса и `\t` для табуляции; для длинных сообщений поддерживаются тройные двойные кавычки. Одинарные строки TOML буквальные. JSON-строки `message`/`extra` используют обычное JSON-экранирование. Значения переменных подставляются один раз, без повторного разбора escape-последовательностей и без rich text.

| Переменные | Доступность |
| --- | --- |
| `{nickname}`, `{serverPort}`, `{bclVersion}`, `{reason}` | Общие шаблоны и ручные сообщения; неизвестная версия — `not reported`, отсутствие причины — `Not specified`. |
| `{playerId}` | После создания серверной сессии; до допуска пустая строка. |
| `{banId}`, `{until}`, `{duration}` | Бан: ID, Unix timestamp окончания или `permanent`, оставшийся срок или `perm`. Причина берётся из `BanList.json` (`Reason`). |
| `{pluginGuid}`, `{pluginName}`, `{pluginVersion}`, `{requiredVersion}`, `{rule}` | Несовместимость плагина/BCL: правило `hardlist`, `blacklist` или `bcl`; отсутствующая версия плагина — `not installed`. |

Команды:

```text
alert <PlayerID|all> <message> <small|large|hint> [seconds] [title="Text"] [titleRu="Текст"] [messageRu="Текст"]
alert all "Welcome, {nickname}!\nRead the rules." large
alert all "Maintenance soon" hint 10 title="Notice" titleRu="Объявление" messageRu="Скоро техработы"
help alert
```

Время бана использует `s/m/h/d`; без времени бан постоянный. Причина хранится вместе с баном и доступна при последующих отказах в подключении. Рассылка `all` форматирует текст отдельно для каждого получателя. Старые/ванильные клиенты пропускаются при отправке alert и получают обычное отключение при отказе, кике или бане: новый UI требует BCL 1.4.2+. Сервер завершает игровую сессию сразу, давая транспорту до двух секунд для подтверждения получения alert. Отсутствие подтверждения не сохраняет сессию.

При запуске и `reloadcfg` сервер отдельно сообщает об успешной или неудачной загрузке PluginsPolicy и Alerts.

`reloadcfg` атомарно перечитывает PluginsPolicy и Alerts; ошибка оставляет предыдущую рабочую пару. Правила применяются к следующим подключениям, уже подключённые игроки автоматически не отключаются. Повреждённые конфиги при старте останавливают запуск сервера. Пути можно задать через `[files] pluginsPolicy = '...'`, `alerts = '...'` в ServerConfig.toml либо аргументами `-pluginsPolicy:"path"` и `-alerts:"path"`. Относительные пути считаются от папки игры. Явно указанный отсутствующий файл считается ошибкой.

Welcome отображается после загрузки игрового мира, спавна персонажа и полного завершения fade.

У welcome есть переключатель «Не показывать больше». Выбор и `updatedAt` сохраняются в PlayerPrefs отдельно для фактического IP:port сервера. Изменив правила, установите новый Unix timestamp в `updatedAt` (секунды UTC, целое число, по умолчанию `0`) и выполните `reloadcfg`. Отличающееся значение сбрасывает скрытие и позволяет показать новую версию.

Клиентский C# API описан отдельно: [BigCityLegacy.Api.LegacyAlerts](../dev-docs/LegacyAlerts_RU.md).

`banRejected` используется при попытке входа уже забаненного игрока; `banned` — при выдаче бана подключённому игроку. Эти шаблоны настраиваются независимо.

## Бан по машине

`ban <PlayerID> <3|4> [time] [reason]` использует fingerprint, который клиент BCL собирает один раз при запуске и передаёт выбранному серверу при подключении. `playerinfo <PlayerID>` выводит его HEX-строку. Это дополнительные типы существующей команды: тип `1` — GUID, `2` — GUID или IP, `3` — GUID или fingerprint, `4` — связанные GUID, fingerprint и IP. Срок, причина и `unban <BanID>` работают для всех типов.

В Windows используются MachineGuid, серийный номер платы/SMBIOS UUID, серийный номер системного диска и постоянные MAC физических сетевых адаптеров.
В Linux используются доступные обычному пользователю DMI-поля, отдельный производный ID BCL от machine-id, серийный номер системного диска/UUID корневой файловой системы и постоянные MAC физических адаптеров.

GUID — базовое основание для блокировки при любом активном типе бана. Для типов `1–3` он проверяется дополнительно и не пополняет другие идентификаторы: совпадение GUID в бане по IP не добавляет новый IP, а совпадение чужого GUID по IP/fingerprint не сохраняет этот GUID. Тип `3` также проверяет машину, но не IP.

Тип `4` отклоняет при совпадении **любого** известного GUID, fingerprint или IP. При таком совпадении он сохраняет новые непустые GUID/IP и пригодный fingerprint в массивах `GUIDs`, `IPs`, `Fingerprints` того же BanID. Основные `GUID` и `IP` сохраняются для совместимости; существующие записи начинают использовать основной GUID без миграции. У одного BanID общий срок и причина. Лимиты — 256 GUID, 256 IP и 128 fingerprints; заполнение лимита не отменяет действующий бан. Удаление бана выключает все накопленные признаки; свойства игрока сохраняются и по-прежнему проверяются только по основному GUID.

При типе 4 общий внешний IP связывает машины за NAT, в семье или VPN в одну бан-запись — это следствие выбранной модели. Старый клиент без fingerprint всё равно проверяется по GUID; тип 4 также проверяет его IP. Для обязательного отчёта задайте `[server] requireFingerprint = true` или `-requireFingerprint` (по умолчанию false). Тогда сервер отклоняет отсутствующий, непригодный или повреждённый fingerprint.
